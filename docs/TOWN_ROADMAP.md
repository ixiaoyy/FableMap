# Town 后续开发路线图

最后更新：2026-08-31

## Purpose

本文件登记 Town/Stardew 主线中已经明确需要、但尚未实现或尚未批准进入开发的能力。它不是“已完成”清单，也不自动授权实施；每一阶段进入代码前仍需建立独立 Trellis 任务、确认范围并更新权威产品合同。

任何 Town 任务在收尾时若主动推迟了玩家可感知能力，必须在归档前把该能力、依赖和触发条件补到这里，避免只留在聊天记录中。

## Precision Gate

当前进入 [现阶段精细化验收门禁](CURRENT_SLICE_POLISH_GATE.md)。门禁完成前，本路线图中所有未完成能力均冻结，不得提升为实施任务；当前只做功能、动作、地图、人物、交互、看板和 UI 的证据驱动精细化。

## Current baseline

截至本次更新，工作区已实现：

- Farm / Town / Cottage / Seed Shop、铁匠工坊、五栋可进入民宅、北侧山麓和南侧湖岸。
- 五栋住宅公共区、静态阻挡的私人内屋、墨子/浩南/阿澜/昊美丽/祥子五名住户。
- Day/Gold/三日萝卜循环、买卖、睡觉、工具选择与本地 IndexedDB 存档。
- 06:00–24:00 时钟、StoredGame v6、八名 NPC morning/day/evening/night 日程、十心基础好感与 Social 名册。
- 新游戏角色创建页、现有 farmer + 8 个 VectoRaith 同风格动画预设，以及旧存档保留原 farmer 的 v5→v6 迁移。

以上仍需真人完整路线验收和干净提交，不因列在本节而自动视为已发布。

## T1 — NPC 日程表现完善

优先级：下一阶段候选。

- [x] NPC 在同一区域内沿短路径走向下一个 anchor，而不是时间节点瞬移。
- [x] 跨区域时增加进门/出门或淡出提示，不要求跨地图连续寻路。
- [x] NPC 动态避让玩家与其他 NPC，避免时段切换重叠或封路。
- [x] 每名 NPC 增加首批白天工作、观察、修缮等轻量环境动作。
- [ ] 增加 morning/evening 的休息、收工或家庭轻量动作；不得与 day 工作 activity 并行。
- [ ] 增加工作日/休息日与商店营业时间；华强离柜后 ShopPanel 不可打开。
- [ ] 增加特殊日程优先级模型，为雨天、节日、事件日预留单一规则 owner。

依赖：当前四段 anchor resolver。天气/星期特殊日程依赖 T3。

## T2 — 好感、送礼与私人房间

优先级：Town 日程真人验收后。

- [x] 为八名 NPC 增加持久好感值和 Social UI；明确上限、显示与衰减规则。
- [x] 每日首次交谈增加好感，重复交谈不刷分。
- [ ] 增加送礼动作、每日/每周限制、通用与个人喜好/厌恶。
- [ ] 增加生日和生日礼物倍率；生日依赖 T3 日历。
- [ ] 私人内屋在对应居民达到确认阈值后解锁；多人家庭房间分别判断 owner。
- [ ] 对话按好感阶段变化，并显示明确但克制的反馈。
- [x] StoredGame v6 保留 friendship migration/forward-fix；Social UI 状态不写入 save。

依赖：T3 日历只阻塞生日，不阻塞基础好感/送礼。卧室解锁依赖好感 identity 与房间 owner 合同。

## T3 — 日历、Season、天气与昼夜表现

优先级：好感基础或日程表现稳定后。

- [ ] 星期、日期、月份/Season 与 HUD；睡觉统一推进日期。
- [ ] 天气生成、保存和次日预告；天气只有一个 domain owner。
- [ ] 雨天影响 NPC 日程、浇水和环境表现，禁止 Phaser 直接修改种田规则。
- [x] 昼夜色调与室内/室外强度差；不把视觉色彩写入存档。
- [ ] 路灯、窗灯、火把或其他逐点光源；需要地图点位与真实夜间可读性评审。
- [ ] 季节作物、地图换季和季节素材需要单独素材/玩法评审。
- [ ] 节日日期与当天建筑营业规则；节日本体在 T5 单独实施。

依赖：现有 minuteOfDay/睡觉日结/StoredGame v6。

## T4 — Town 职业与地点功能

优先级：按玩家需求逐项批准，不整包实施。

- [ ] 墨子：木匠修缮/农场建筑服务。先定义一个真实用途，不建立通用建造平台。
- [ ] 昊天：工具升级。用户已明确现阶段不重要，保持低优先级。
- [ ] 浩南：山路安全、采石或矿洞引导；采矿系统单独规划。
- [ ] 阿澜：染色、布艺或地图信息服务；先确认是否产生物品/经济。
- [ ] 昊美丽：针线、工坊护具或装饰修补；不提前建设装备系统。
- [ ] 祥子：码头、船只与钓鱼入口；钓鱼系统单独规划。
- [ ] 公告板委托、诊所/社区设施、更多商店与代表性公共建筑逐项评审。

依赖：对应核心玩法先成立，再开放 NPC 服务；禁止用空商店面板假装功能完成。

## T5 — 人际事件与小镇内容

优先级：好感与日历稳定后。

- [ ] 家庭成员之间的同屋对话和共同场景。
- [ ] 心事件/个人事件；事件选择是否改变好感需单独确认。
- [ ] 邮件、食谱或小礼物回馈。
- [ ] 节日、集市、生日聚会与小镇公共活动。
- [ ] 更多居民、家庭和住宅只在现有八名 NPC 真人体验稳定后扩充。
- [ ] 婚恋、结婚和同居属于远期独立里程碑，不因基础好感自动进入范围。

## T6 — 玩家外观扩展

优先级：取得同风格专用素材后。

- [x] 新游戏先选择真实生效的角色预设，并随 IndexedDB 存档恢复。
- [x] 旧存档继续保持原 farmer，不恢复旧 Ninja/Samurai 外观或 localStorage 字段。
- [ ] 引入与 VectoRaith 16×32 比例协调的专用分层玩家素材，至少覆盖发型、上衣、下装和鞋子。
- [ ] 分层素材必须为四方向完整动画，统一锚点、遮挡顺序和工具动作；不得只做创建页静态头像。
- [ ] 增加发色、衣色等有限调色时，颜色语义由 appearance contract 保存，贴图 URL/frame 仍只属于 client。
- [ ] 是否允许游戏内通过衣柜重新编辑外观，需在角色创建稳定后单独确认，不与首版自动捆绑。

依赖：明确许可且允许 Web/CDN 分发的同风格素材；CC-BY-SA/GPL 等强 copyleft 项必须另行评审，不能为增加选项混入比例或画风不一致的包。

## Explicitly deferred systems

以下能力已记录但当前仍未批准：

- 完整 NPC 寻路、天气/节日复杂日程、程序化事件调度。
- 送礼、生日、私人内屋解锁、关系对话、心事件与婚恋。
- Season、天气、季节作物、路灯/逐点光源和节日。
- 工具升级、通用建造、采矿、钓鱼、复杂经济和任务系统。
- 发型、上衣、下装、鞋子分层换装与游戏内衣柜编辑。
- Expedition、战斗扩展、灵兽、肉鸽、撤离和妖潮塔防。

## Promotion rule

路线图条目进入实施前必须：

1. 明确玩家价值与最小可玩闭环。
2. 核对前置能力是否完成并经过真人反馈。
3. 创建独立 Trellis PRD；复杂能力同时提供 design/implement。
4. 更新 `PRODUCT_BRIEF.md` 与 `WHAT_NOT_TO_BUILD.md` 的当前边界。
5. 只运行与该批直接相关的最小检查，不用路线图作为扩建测试矩阵的理由。
