# 镜像岛产品简报

## 一句话定位

一款东方风格、未来拥有独立世界观与剧情的星露谷式单人像素生活 RPG。当前先补齐已选定的成熟生活模拟基础系统，完成后停止横向仿照并进入镜像岛原创转型；普通主矿洞战斗属于基础盘，节庆内容、婚恋与镜门远征不在当前范围。

## 核心合同

- 第一张正式地图结构固定：玩家农场向右连接小镇，北侧预留山地/矿区，南侧连接河流/湖泊；不再反复调整总体布局。
- 玩家、资源、背包、制作和农田由本地 GameSession 唯一处理；Phaser/Vue 发送命令并渲染 snapshot，不经过实时后端。
- 第一阶段已经完成并生产验收：World Foundation、Farm Showcase、`life-loop-v1`、Town Gate A/B/C 与 Town Population MVP。玩家可以在正式 Farm/Town/Cottage/Seed Shop 间移动，完成三日萝卜生活循环，并与华强、昊天、阿禾交互。
- 房屋、伙伴工作和基地权限保留为后续主线能力，不进入首个纵向切片。
- 当前托管 Web 入口是纯本地无账号试玩；不显示或调用注册、登录、论坛账号、账号设置或云存档入口。
- 玩家存档、背包和世界状态由本地 GameSession 处理并写入 IndexedDB；实时玩法不经过服务端。
- `One Beautiful Slice` 已在真实生产浏览器通过验收并冻结为 Farm v1；除明确碰撞缺陷外，不再重排构图或继续添加装饰。
- 客户端技术栈固定为 Phaser 4 + Vue 3 + TypeScript + Vite + Tiled。未来桌面版与 Steam 目标采用 Tauri 2，但当前不引入 Tauri/Rust/Steam；GameSession 通过 SaveRepository 与当前 IndexedDB、未来 FileSystem adapter 解耦。
- Ninja Adventure 只保留室内技术占位；VectoRaith Farming Sim Gate C 已冻结并正式成为 Farm v1 美术底座，Town Gate A 也已按同一完整图集正式化。生产直接加载 6 张官方 Original/16×16 图集。

## 长期玩法方向

长期核心循环是：家园种田、采集、钓鱼与采石 → 将不同产出投入跨日目标 → 看见小镇设施与居民生活永久改善 → 使用新设施提高后续生活效率 → 继续经营农场与建立关系。

- 参考《星露谷物语》的抽象进度结构：多种日常活动共同服务长期目标，每次完成既有即时用途，也有可见的社区变化；不复制其名称、收集表、地图、角色、文本、UI 或美术。
- 转型前按仓储出货、非战斗技能、浅层矿洞/冶炼/工具先行切片、完整 120 层矿洞与战斗、四季、农田自动化、鸡舍草料、加工、烹饪、小镇共建的依赖顺序完成基础盘；阶段可以拆小，但不能把后续参考机制永久删掉。
- 每个阶段规划前必须先核对当前代码和《星露谷物语》对应机制的可追溯资料，记录参考事实与经用户批准的偏离；数量、时长、容量、概率和层数不得由 AI 自行猜测。
- 小镇共建作为基础盘最后的长期集成阶段；三个 closed project 足够验证，不建设通用 Bundle/Quest 平台。
- 地表资源已提供基础镐/镰刀、石料/植物纤维、固定石块和杂草；浅层无战斗矿洞可作为先行 planning，但后续完整 120 层矿洞、生命、武器、敌人、掉落、Combat skill 与冒险家公会已明确为转型前必达项。
- 家园猫狗保持生活伙伴定位，不发展为战斗、远征、自动化或复杂养成框架。
- 东方志怪和《聊斋》属于后期独立异闻故事世界；普通探索继续使用像素世界，关键剧情未来可单独评审 CG、文字和授权语音。
- 用户已选定 A「清新田园」作为后续美术方向：明亮配色、清晰像素轮廓与轻快田园比例，先统一五件工具和小屋内外，再扩展农场与小镇。美术以质量和风格统一为准，不设成熟素材与自制素材比例，也不要求全部开源；现成素材达不到要求时可以自行制作。始终坚持“一张精美地图优先于十张粗糙地图”。示例获选不等于正式素材已替换，制作与发布标准见 [游戏美术资源规范](IMAGE_ASSETS_SPEC.md)。
- 生活世界中的探索采用“看见异常 → 获得线索 → 主动尝试 → 明确反馈 → 留下变化”的手工设计语言，优先复用现有地图、工具、时间与 NPC，不以战斗、物理沙盒或通用框架制造体量。详细原则见 [镜像岛探索设计原则](EXPLORATION_DESIGN_PRINCIPLES.md)；该文档只作为未来候选评审依据，不改变当前基础盘 child 顺序，也不自动授权任何探索功能实施。

## 试玩进入体验

2026-09-06 用户明确要求正式角色支持上中下分层及性别/换装：头部、上装、下装独立组合，衣服不按性别锁定；新游戏可定制，继续已有农场后可打开外观界面修改并保存。取消九个整人预设的选择入口。角色功能在正常 `/` 运行，不依赖候选链接；切换只改变外观，不影响背包、金币、位置或世界进度。

玩家访问 `/` 后直接看到“新游戏 / 继续游戏”，客户端不发起 Keycloak/OIDC 请求。同一 origin + 浏览器 profile 只使用一个固定本地试玩槽；清除站点数据会丢失进度，且不支持跨设备同步。

旧账号派生的 IndexedDB 记录保持原样但暂时不可达，不枚举、删除、覆盖、合并或迁移。Keycloak、论坛 OIDC bridge 和数据库基础设施保留，独立注册关闭。

## 数据原则

- Keycloak 和游戏数据库分库/分凭据，游戏库不复制密码或论坛凭据。
- 旧 `localStorage` 角色名、外观和进度全部丢弃；新版只精确删除已知 `farm-game.save.v1`–`v4` 键。
- IndexedDB 保存本地 GameSession；Keycloak、Prisma/PostgreSQL 作为未启用的身份及未来云存档、成就和排行榜基础设施保留，不进入客户端启动或实时循环。
- 开发阶段的本地玩法存档只保证 current schema：新增状态时不迁移、回填、备份或兼容此前开发版本，验收从清理站点数据后的新游戏开始；current 版本内的严格解码、原子保存、刷新恢复仍必须正确。该政策不适用于论坛、身份、数据库、媒体或部署数据。
