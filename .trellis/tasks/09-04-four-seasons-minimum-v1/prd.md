# 四季最小内容 v1

## Goal

让 absolute Day N 真正进入春夏秋冬，并让每季都有足以验证种植、采集、天气、视觉和经济选择的最小内容。

## Background

- `calendarAt()` 已能推导四季，但当前 `playableCalendarAt()` 永远返回 spring；六作物、采集窗口和地图视觉均只覆盖春季。
- 当前 Day 28→29 已验证连续日结，因此季节切换必须沿用同一 candidate/save 边界。

## Requirements

- Day 28→29、56→57、84→85 和 112→113 分别切换季节/年份；只保存 absolute day，避免重复日期字段漂移。
- 每季提供少量不同成长周期/再生特征的作物、地表采集和天气权重；所有需求均能在该季正常获得。
- 户外地图视觉使用已评审的季节 profile 或受控源码表现；Collision、stable IDs、出口和 NPC 身份不随季节变化。
- 跨季作物的枯萎/保留规则、草地和后续动物依赖必须在日结中一次确定，保存失败不得半切换。
- 提供已有 NPC/service schedule 所需的精确 calendar markers：季节/日期、普通雨与绿雨、关闭商店的节庆日、Night Market 等被动节庆例外及固定体检日。markers 的日期/优先级必须先从 1.6.15 资料核对；本 child 只接通日历与营业规则，不实现节庆场景、活动或奖励。

## Acceptance Criteria

- [ ] 玩家可从春 28 睡到夏 1，并连续走完四个季节边界和 Year 2 Spring 1；日期、天气、商店、采集与视觉一致。
- [ ] 四季各自按已核实的参考季节规则提供可玩的作物/采集选择；冬季与其他季节的差异明确记录，不为满足对称数量而虚构普通作物。
- [ ] 跨季日结失败可重试同一候选，不重复成长、改变天气或多次处理作物。
- [ ] 墨子木匠日程在四季可达状态下覆盖夏季 18 日、普通雨/绿雨、关闭商店节庆与 Night Market 例外；日历 marker 与 service resolver 共用同一事实，不由 UI 猜测。

## Reference Discipline

- 四季均为 28 天是当前代码与参考作品共同事实；作物、采集物、天气权重和换季规则在 child 研究中从资料逐项核对。
- 本任务只因父任务“系统覆盖而非内容平权”缩减内容量，不预先猜测每季物品数量；任何数量与跨季作物规则都要在 child PRD 中注明来源或用户决定。

## Out of Scope

- 节庆场景/活动/奖励、生日、季节剧情、冬季大型独占地图和达到参考作品的作物数量；为既有营业合同提供节庆 calendar marker 不等于建设节庆内容。
