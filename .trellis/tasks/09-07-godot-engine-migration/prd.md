# Godot 与 GDScript 引擎迁移

## 目标

将项目的后续游戏开发迁移到 Godot + GDScript，正式产品优先面向 Windows/Steam，保留同工程 Web 试玩能力。用户于 2026-09-07 明确要求先迁移引擎；本任务不继续讨论或实现真实城市生成，也不更改游戏名称。

## 基线与边界

- 基线为本地 main 的 02ee7d0c；工作区开始时干净。
- 现有 12 张 Tiled 地图、已登记美术和当前 TypeScript 玩法是移植依据；规则数量、价格和时间不随引擎迁移重定。
- 当前 Phaser/Vue 客户端在 Godot 功能对齐前保留作对照；不发布缩水替代品，不建立第二个公开游戏路由。
- 后端、身份、论坛、数据库、CDN 对象和部署环境不修改，不连接数据库。
- 开发旧档不迁移；Godot 使用独立版本和存档空间，不覆盖原浏览器试玩档。

## 需求

1. 建立可在 Godot 编辑器打开的 GDScript 工程，地图、建筑与角色素材可查看和调整。
2. 复用已授权素材，保留来源、SHA-256 和署名；生成资源及引擎二进制不进入 Git。
3. 打通当前地图的显示、遮挡、碰撞、区域转换和玩家操作，保持现有空间布局。
4. 逐项移植现有玩法：采集/种田、背包/制作/仓储/出货、时间/体力/天气、商店、钓鱼、NPC/宠物及外观。
5. 提供 Web 与 Windows 导出方式；手机 Web 首次启动、触控及同版本保存恢复必须真实验收。
6. 用户明确要求完整迁移后，本地默认开发/构建随代码对齐切换，供真人审查；公开部署仍必须先完成真人验收并另行获得授权。

## 验收

- 工程解析与资源导入通过，生成地图可以在编辑器检查，不将整张截图冒充可编辑地图。
- Windows 与 Web 产物实际生成；明确区分导出成功与真人玩法通过。
- 每项旧玩法均记录未移植/已移植/已验证状态；不将第一批基础工程称为完整迁移。
- 坏档与保存失败不静默覆盖；旧 Phaser 存档和外部服务保持完整。
- 最后统一移除被替代的前端运行入口和过时规范，留下明确回滚基线。

## 非目标

Steam SDK、移动商店上架、城市/OSM 生成、新玩法、新素材制作、改名、提交、推送和部署。
