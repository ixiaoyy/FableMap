## 目标与玩家价值

在镜像岛小镇外规划一座可反复探访的独立庄园，以《秘密花园》的完整人物关系和主要故事为内容基础，让玩家经历发现秘密、照料花园、与人物共同生活以及庄园重新恢复温暖的过程。

体验的三个可见结果是花园生长、孩子们建立信任、家庭关系发生变化。地图、园艺和对话共同承载故事，摆放建筑、交付材料或播放剧情梗概不能代替完整篇章。

## 已确认事实与当前基线

### 用户决定

1. 庄园是小镇外新增的独立地点，保留玩家现有农场布局。
2. 内容覆盖完整《秘密花园》故事，包含庄园主人、孩子、园丁和相关人物。
3. 此前只做外院、长廊、开门和修复的短流程已被扩大，不能继续将其作为最终交付范围。
4. 本轮只落盘详细规划，明确暂不实现。
5. 玩家使用现有角色还是扮演玛丽，尚未选择。

### 已检查的工程事实

- 检查基线为 `8c23ad27`，分支 `codex/godot-engine-migration`；创建任务前工作区干净。该分支仅是检查基线，不是本任务获批的开发分支。

- `GameSession` 已有区域切换、工具、对话和关键候选保存，没有本篇章的钥匙、锁门、章节或花园成长状态。
- 农田规则和存档农田校验限定 `farm`，不能直接当成现成的多区域种植能力。
- NPC 日程、社交和 UI 依赖固定内容表，故事角色需要完整登记和路由。
- 开发存档只保证新版本完整状态与同版本恢复，不维护旧开发档迁移。准确位置见 [工程证据](research/evidence.md#工程证据)。

## 产品要求

### R01 — 独立庄园与原有世界

- 从小镇的一处可解释入口连接庄园道路；精确点位待地图评审，不占用山地/矿区或湖岸既有出口。
- 保留 Farm/Town 总体构图、稳定区域 ID 和生活入口。庄园不接管玩家农场、小屋睡觉、商店或每日委托。
- 篇章可暂缓、离开并继续，不成为基础生活或存档恢复的前置条件。
- 原著地域通过文学设定和美术表达；采用手工虚构地图，不使用真实坐标、定位或现实路网。
- 返回农场后现有身份与生活规则保持；如选择玛丽视角，控制权和外观恢复须先解决 O01。

### R02 — 完整主线与明确终点

- 按 [C01–C08](story.md#八章内容规划) 覆盖原著全部 27 章的主要情节与人物作用，不要求逐句复制或制作每个一笔带过的房间。
- 到达、发现花园、认识迪肯、发现科林、共同进入花园、持续成长、家庭记忆、主人归来均有具体呈现位置。
- 主人归来与父子重逢是必交内容，不能停在开门、清理或开花阶段。
- 结局前有多次共同生活，避免一次交材料直接触发人物性格或行动能力突变。
- 采用固定主线与可选了解；对话选择表达态度，不默认增加多结局或复杂分支网。
- 制作可以分批，最终范围不缩减。阶段验收不等于整个任务完成。

### R03 — 人物完整性与行为

- 核心人物：玛丽、科林、迪肯、本、克雷文先生；支撑人物：玛莎、苏珊、梅德洛克太太、克雷文医生；莉莉亚斯通过回忆和遗留物呈现。
- 科林、迪肯、老园丁是不同角色；庄园主人与医生也必须分清身份和称呼。
- 每名出场人物有可识别外观、剧情职责、出现条件和阶段对白；见 [人物清单](story.md#人物与关系)。
- 主要人物参与查看植物、带路、园艺和共同休息等行动，不全部退化为站桩任务发布者。
- 剧情站位不被普通日程覆盖，结束后恢复当前章节合法日常位置。
- 庄园人物默认不加入现有八名居民的送礼、委托、营业和数值好感体系；关系由明确事件表达。
- 未见角色和未知秘密不得提前进入对白、人物介绍或目标说明。

### R04 — 场景与探索

- 提供入口、外院、主楼公共区、关键卧室、园艺工作区、林间道路和秘密花园，区域拆分见 story.md。
- 用建筑轮廓、长廊、窗景和有限封闭空间表达规模，不以空房间凑数。
- 线索具备异常、提示、尝试、反馈和世界变化。鸟鸣、地面痕迹、藤蔓与门缝配套文字或视觉反馈，不要求像素级点击。
- 钥匙藏点和隐藏门固定，不采用随机掉落、每日重抽或不可逆错过。
- 锁门同时约束通行、NPC 路径和场景表现；永久变化不得早于保存成功。
- 轮椅路线需覆盖门洞、转角、停留点与人物避让，不能只让普通玩家体型通过。

### R05 — 园艺与花园成长

- 建议采用初见、整理、萌发、盛放和结局日常表现，具体阶段画面须通过样板评审。
- 分清仍活着的植物与杂草，保留旧花园的历史，不把全部地面推平后换成普通农田。
- 使用有限固定花床、玫瑰支架、旧小径和休息地点；复用工具输入与背包合同，定向处理庄园目标。
- 浇水、整理、种植参与剧情，不以全局花卉经济、自由装饰或任意土地种植为前置。
- 每次成功都有可见变化；永久修复不受普通资源再生影响。
- 花园外观与人物成长相关但不共用一条数值，不能用木材数量或卖花收入直接决定科林的行动变化。
- 材料、耗时、体力、生长间隔尚未批准，列入 O03；不擅自给出掉率、等待天数或强制劳动总量。

### R06 — 时间、节奏与继续

- 开始前、推进中和结局后均可返回原有生活；暂停数日不会永久丢失主线。
- 时段/天气条件可再次达到，并有可理解提示，不用隐藏日期卡进度。
- 关键对话和演出协调时钟、输入与已有弹窗，不能中途凌晨日结或出现底层工具动作穿透。
- 普通活动是否沿用世界时间、花园如何表现季节由 O02 决定，不借此自动实现全局四季。
- 中断后从最近完整剧情节点继续，不保存每帧动画，不离线推进故事。
- 可复读已知信息；跳过演出需明确摘要和继续条件，状态完成不等于真人已观看。

### R07 — 人物成长与表达

- 孤独、失去亲人、被忽视、友谊、照料与关系重建通过行为、空间和对话呈现。
- 保留玛丽的关键发现与主动作用，现有玩家参与不能把她的故事全部转移给玩家。
- 科林有自己的愿望和选择，不只是被搬运或被交任务的对象。
- 轮椅、站立、行走、奔跑作为故事阶段，不设计病情数值、诊断小游戏或购买康复的机制。
- 已故夫人通过记忆表达，不自动新增真实幽灵、复活或超自然技能。
- 使用自然的原创中文改编对白，不照搬未知授权现代译本、绘本或影视对白。

### R08 — 结局后的庄园

- 重逢后门锁、花园、人物位置和对白共同进入结局状态，刷新与睡眠不倒退。
- 可继续探访人物、观赏花园、有限照料并了解已知背景，不只剩片尾字幕或关闭入口。
- 以人物与环境变化为主要回报，不默认加入赠送房产、第二家园、婚恋或无限收益。
- 结局重播仅保留后续评审入口，不作为隐含必需能力；若采用，不重复结算或回滚世界。

### R09 — 美术、声音与来源

- 延续清新田园像素语言，统一比例、密度、左上光照、描边与 UI，庄园用浅石墙、藤蔓和木作形成特征。
- 用遮蔽、整洁程度、花量、环境声和人物活动区分冷清与复苏，避免灰黑滤镜遮住玩法信息。
- 清单覆盖成人、儿童、轮椅、园艺动作、鸟类和花园阶段，不用静态头像替代必要世界动画。
- 原著、译文、改编、视觉参考、字体与音频分别登记；正式采用前核验实际用途，不直接拿影视版外观或音乐作为生产资源。
- 二进制遵守媒体登记、不可变对象、真实 prompt sidecar 和随产品致谢要求，概念图、技术占位与正式素材分别标记。

### R10 — UI 与输入

- 对话、回应、观察提示、人物名字、已知线索和暂停支持键盘、鼠标、触摸。
- 只显示已发现信息，提供简短回顾，不制作提前揭晓秘密的全知清单。
- 桌面、窄屏、Web 200% 缩放与中文长句下保持可读可操作；线索不只依赖细小文字、颜色或声音。
- 默认中文文本与字幕，全语音和多语言翻译不属于隐含要求。

### R11 — 本地状态与失败

- 章节、发现、门锁、花地和完成事件由唯一 `GameSession` 保存，场景、对话工具与 UI 不直接推进。
- 单次操作在同一候选内完成检查、必要扣除与变更，保存成功才发布。
- 重复点击、进入、刷新和重试不重复扣除、奖励或播放已完成强制场景。
- 保存失败保持原有可玩状态并提示重试，重试沿用同一候选，不重新结算。
- 校验完整状态和前置关系，未知 ID、越级完成、非法位置或不兼容版本明确拒绝，不静默补齐。
- 沿用开发档重置政策，不做旧档 migration、备份和兼容矩阵，也不自动清理当前存档；实施时明确新版本及人工新档验收步骤。

### R12 — 工程与授权边界

- Godot/GDScript 单一运行时，固定本地故事，不引入服务器、账号、数据库、LLM 或在线生成。
- 新通用能力先比较既有实现与成熟开源候选，只采用必要的窄对话/演出能力，不建设通用 Quest、后台或编辑平台。
- 不依赖尚未实现的矿洞、四季、加工整套系统；真实依赖先记录，不顺手扩建相邻任务。
- 数据库结构变更为零，本地存档字段变化不称作 SQL migration。
