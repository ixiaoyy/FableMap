# 转型前生活模拟基础盘

## Goal

在不复制《星露谷物语》品牌表达的前提下，用十个独立纵向切片，在这十个已选基础系统内完整对齐 1.6.15 机制合同，再从已验证的生活模拟底座进入镜像岛原创转型。

## Background

- 当前工作区 current v12 已有时间、天气、体力、睡眠、六种春季作物、自由农田、树木/采集/钓鱼、地表采矿/除草、背包、买卖、NPC 日程/好感/送礼/委托和家园宠物。
- `domain/recipes/definitions.ts` 当前只有一个制作木斧的配方；仓库没有箱子储物、农场出货、可摆放物、技能经验、矿石冶炼、四季玩法内容、农田自动化、家畜、加工或烹饪 domain owner。
- `playableCalendarAt()` 当前把所有 absolute Day N 继续投影为 spring-content；四季日历纯函数存在，但不是当前玩法状态机。
- 已规划的 `09-04-town-community-ledger-v1` 提供多种日常产出汇入长期社区改善的中期目标，并已作为本任务子阶段；它当前仍是 planning。
- `09-04-surface-mining-v1` 已完成生产实现、自动检查和 Farm 浏览器路线，但尚未得到 commit 授权或完整真人验收；后续子阶段不得混入其暂存集。
- 用户于 2026-09-04 先确认浅层无战斗矿洞作为阶段性切片，随后明确它只是此前阶段计划：后续完整矿洞与战斗肯定要有，并要求转型前先完整参考《星露谷物语》的基础玩法。战斗因此不再是长期排除项；每项仍须证据优先，不接受 AI 自行猜测。

## Requirements

### R1 — 完成策略

- “完全参考”限定为完整对齐本任务列出的十个系统，不代表自动纳入 Stardew 的所有剧情与内容；不复制参考作品的品牌、文本、角色、地图布局、UI、美术或音乐。任何因阶段拆分暂未交付的系统内机制必须有明确后续 child，不能写成永久排除。
- 每个子阶段必须形成至少一个可重复玩家闭环，包含获得/投入、时间或资源约束、明确结果、current save 恢复和可理解反馈；只展示面板、图标或未来入口不算完成。
- 同一时间只启动一个拥有实际代码的子任务；前一阶段通过最小自动检查和目标真人路线后，再进入下一个阶段。
- 父任务只拥有需求源、阶段顺序、跨阶段不变量和最终转型门禁，不直接承载生产实现。
- 每个 child 收敛 PRD 前必须先核对当前代码与《星露谷物语》对应机制的可追溯资料，明确记录“参考事实”和“经用户批准的镜像岛偏离”；没有来源或用户决定的数量、时长、容量、层数和概率只能保持开放，禁止自行补值。

### R2 — 十个独立阶段

1. **农场仓储与出货 v1**：按用户确认校正 12-slot Hotbar、12→24→36 背包与普通物品 999 stack；交付 36 格箱子、农场出货箱、隔夜结算和后续设备共用的摆放合同。
2. **技能与配方解锁 v1**：先让现有种田、采集、钓鱼、采矿四类劳动形成 0–10 级、等级配方与 5/10 级职业选择；战斗技能随完整矿洞 child 接入，最终五类技能都遵守同一参考合同。
3. **浅层矿洞、冶炼与工具升级 v1**：作为低风险先行切片建立楼层、重置、电梯、矿石、熔炉/金属锭和工具升级底座；该 child 暂不放敌人不代表产品永久无战斗。
4. **完整矿洞与战斗 v1**：把先行矿洞扩展为参考作品式 120 层进程，并补齐生命值、武器、敌人、掉落、战斗技能与对应服务/恢复闭环；具体规则逐项以 1.6.15 证据收敛。
5. **四季最小内容 v1**：真实春夏秋冬轮换，每季只提供足以验证种植、采集、天气和视觉切换的最小内容。
6. **农田自动化 v1**：参考作品的三级洒水器、稻草人和土壤肥料；洒水器/稻草人复用摆放合同，肥料保存在农田 tile 状态。
7. **鸡舍与草料 v1**：可选农场位置的鸡舍/筒仓建设、基础鸡舍四只鸡、每日照料、蛋、草地与干草闭环；其他畜种不进入本基础盘，繁殖/野外袭击等鸡系统细节须在 child 中按参考事实收敛。
8. **基础加工 v1**：少量作物/动物产出进入有时长的加工设备并增值；不做物流网络或通用自动化平台。
9. **厨房与烹饪 v1**：农舍第一次升级、厨房/冰箱、已学习配方、原子耗材和餐食；菜谱内容量可以缩减，buff 是否保留须按参考事实单独收敛。
10. **小镇共建簿 v1**：把已有及新增日常产出汇入三个封闭社区项目，并兑现地点、居民和功能变化。

### R3 — 阶段依赖与顺序

- `surface-mining-v1` 完整收尾后，先实施仓储/出货/摆放；它是洒水器、加工设备和农场设施的持久位置基础。
- 技能解锁先于需要等级门槛的矿洞/工具与自动化配方。
- 浅层矿洞先验证楼层/矿石/冶炼状态；完整矿洞与战斗在其后复用并扩展同一 floor identity 与存档合同，不能另建第二套矿洞运行时。
- 完整矿洞/冶炼提供稳定金属与战斗材料后，才实施四季后的农田自动化。
- 四季必须先稳定，再让草地、草料、鸡和季节性生产依赖它。
- 鸡蛋来源先于动物加工；基础原料与加工产物稳定后再实施厨房。
- 共建簿最后集成各日常系统，但不能重复实现它们的规则。

### R4 — 共享产品与技术边界

- 唯一运行链保持为 Phaser/Vue → typed GameCommand → GameSession/domain → SaveRepository → IndexedDB；客户端只发送意图并渲染只读 snapshot。
- 开发阶段每个里程碑只定义一个完整 current save；不为此前开发版本建设 migration、回填、隐藏备份或补发队列。current decoder、原子保存、保存失败反馈和同版本恢复仍是门槛。
- 不增加实时服务依赖、账号、云存档、PostgreSQL 查询或 SQL migration；不恢复 RPGJS/Colyseus 双运行时。
- 复用正式 16px Tiled 世界与已登记媒体；新增素材继续执行官方来源、固定版本、许可、manifest 和 Git 媒体二进制为零的合同。
- 参考作品的摆放合同已经消除“固定插槽”分支：小型物件按各自允许区域放在合法空格；农场建筑通过建造界面在 Farm 内选择完整无阻挡 footprint，并可从对应服务再次移动。镜像岛可以缩减内容数量，但任何位置限制偏离都必须在 child PRD 中列明并重新确认。
- 不把上述格位/footprint 合同扩张成无边界地图编辑器；合法位置仍由 Tiled mask、动态占用、出口、NPC 与资源规则共同验证。

### R5 — 转型停止线

- 十个子阶段全部通过后，执行一次只读“转型准备度”审查：确认主要日常行为均有即时收益、长期用途、时间选择和可见世界反馈。
- 审查通过即冻结继续追加参考作品功能；之后的新任务必须先回答“它如何体现镜像岛自己的世界、关系或长期变化”，不得因参考作品拥有某系统就自动建设。
- 战斗与完整主矿洞现在属于转型前完成条件。节庆场景/活动/奖励、婚恋、博物馆、成就、多人、完整收藏和大量内容填充仍未因本次决定自动进入范围；日程所需 calendar marker 只是已选系统的依赖。若后续要求纳入节庆玩法本体，需像战斗一样明确更新任务树。

## Acceptance Criteria

- [ ] 当前 `surface-mining-v1` 已取得真人确认、完成独立 commit/归档，后续阶段没有混入其 Git 暂存集。
- [ ] 十个子阶段均有独立 PRD；复杂阶段在启动前还有 design/implement，且一次只启动一个实际实现任务。
- [ ] 玩家可完成仓储与隔夜出货、五类技能成长、120 层主矿洞、战斗/生命/武器/敌人/掉落、矿石冶炼与工具升级、四季轮换、有限农田自动化、鸡与草料、基础加工、烹饪和三项小镇共建闭环。
- [ ] 各系统都由 domain/current save 拥有规则，刷新/继续和保存失败不会重发奖励、重抽结果、丢失位置或部分扣除资源。
- [ ] 每阶段至少完成目标业务路线及桌面/手机、键盘/鼠标/触摸、200% zoom 中与该阶段相关的人工验收；自动检查保持窄且风险匹配。
- [ ] 整个基础盘没有新增数据库 migration、实时后端依赖、未经评审媒体二进制或通用内容/建造/任务平台。
- [ ] 最终准备度审查确认基础盘足以承载原创系统，并建立一个新的镜像岛转型任务；父任务不直接夹带转型实现。

## Out of Scope

- 达到《星露谷物语》的内容数量、数值规模、地图结构、文本、角色、UI、美术、音乐或具体收集设计。
- 转型前的节庆场景/活动/奖励、恋爱婚姻、博物馆、成就、多人和完整收藏；日程 calendar marker 不属于节庆玩法。战斗、敌人、武器与生命值已移入 `full-mine-combat-v1`，不再属于本清单。
- 全世界家具编辑、物流带、自动寻路生产、无界程序生成框架、通用 Quest/Bundle/Recipe/Building 编辑平台。
- 任何镜门远征、Cargo、撤离、抓宠、肉鸽或塔防提案。
